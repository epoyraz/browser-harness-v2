Executive verdict

Do not describe the current head as release-ready or privacy-clean.

The async client, dead-browser recovery, verified skill loading, recorder concurrency, UTF-8 handling, and package allowlist are credible improvements. The remaining blockers sit at the boundaries where factual routing becomes action: Git index state, click ownership, popup attribution, and macOS consent. Those boundaries need to fail closed.

The current head is suitable for continued internal development. It is not yet suitable for a public release, strict parallel-isolation claim, or unattended multi-browser operation.

Scope and method

The review covers the rolling two-day range aa5147f..8ac2873, including the seven-commit batch added after the initial review. Today’s Claude conversation was read as design and implementation context, then checked against Git and the current code rather than treated as proof.

High BH2D-002

The inert-click fallback can activate a control behind an overlay

Commit 9037307 · harness/ops/page.py:1567–1655

The DOM retry selects __bh.refs[ref] before document.elementFromPoint(x, y) whenever a ref exists. That special case was needed for an unpainted zero-rectangle Apply control, but it now bypasses hit testing for every referenced element.

elementFromPoint = "cover"
button handler hits = 1
reported modality = "dom"
reported mutations = 0

Impact

A modal, cookie sheet, or other overlay no longer owns the point. The harness may synthesize activation on the obscured element underneath.

Recommendation

Use the ref-only path solely when the intended target has no usable rectangle. Otherwise require the point hit to be the target or its descendant.

Comparative evidence

The base revision left the covered control at zero handler hits. Current head activated it once.

Acceptance test

Keep both real-Chrome fixtures: the zero-rectangle control activates, while an ordinary covered control never does.

High BH2D-003

macOS approval is not scoped to the browser being connected

Commit c88b4ad · harness/connect/macos.py:37–76 · daemon.py:171–203

The AppleScript searches every process named Google Chrome for an English consent sheet and presses the first English Allow button. The daemon starts it without the resolved browser, profile, PID, or endpoint.

Impact

Multiple Chrome instances can lead to approval of the wrong WebSocket. Localization breaks matching. Canary, Arc, Dia, Edge, Brave, and Chromium are discoverable but cannot be approved by this helper.

Recommendation

Carry resolved endpoint identity into the handshake. Scope automation to the matching application and PID, and arm it only while a newly created WebSocket handshake is actually pending.

Positive result

The commit correctly identified that Chrome exposes the HTTP endpoint before WebSocket consent, so HTTP readiness cannot terminate the approval pump.

Acceptance test

With two browser instances and a decoy sheet, only the resolved process is touched. Non-Google variants either work explicitly or return a typed unsupported result.

High BH2D-004

Foreign target events still terminate another tab’s click wait

Commit 8a5fcf1 · harness/ops/page.py:1063–1080 and 1463–1485

The commit correctly filters stored target deltas with openerId == self.target_id and replaces the bounded-deque length cursor with a monotonic sequence. The active waiter still regards every browser-level Target.targetCreated event as a consequence of the current click.

requested settle = 300 ms
foreign target event = immediate
click returned = 1.0 ms
reported new_targets = []
own popup arrived = 80 ms after dispatch, after return

Impact

A concurrent worker can wake this click early. The real popup may be missed and the inert-click fallback may then repeat an activation.

Recommendation

Give the waiter the same opener-aware predicate as the target-delta bookkeeping. Do not use session ID for browser-level target events; they do not carry one.

Positive result

The new sequence counter fixes the permanent post-sixteen-target blind spot and should remain.

Acceptance test

A foreign popup neither wakes nor enters the delta; an owned popup arriving inside the settle window is returned exactly once.

Medium BH2D-005

The zero-iframe fast path can miss a dynamically inserted OOPIF

Commits f1183df, 65b908a, cf2c2cb · harness/ops/page.py:1818–1907

If DOM.performSearch reports zero iframe hosts at one instant, frames() skips the auto-attach quiet window entirely. A real-Chrome page that inserted a cross-site iframe 80 ms later returned no frame on the first call.

current head: [] in 5.2 ms
600 ms later: cross-origin iframe present and discoverable
base revision: waited about 246 ms and caught it on the first call

Impact

prepare_application() can miss an SPA-inserted application or bot-wall frame and classify a reachable page as empty.

Recommendation

Retain the fast probe but give zero a short bounded observation window, preferably driven by DOM or target events rather than a fixed sleep.

Medium BH2D-006

Popup cleanup is causally correct but temporally incomplete

Commit adca98b · harness/ops/parallel.py:59–84 and 224–256

Following the openerId descendant chain is safer than comparing global target snapshots. Cleanup nevertheless takes only one snapshot immediately after the item function returns.

popup scheduled = 150 ms after item return
first cleanup descendants = 0
popup visible to next item = 1
second cleanup eventually closed it

Impact

A late popup can survive into the next job on a reused worker tab, violating the claimed between-job isolation boundary.

Recommendation

Add a bounded target quiet window or a second opener-chain scan before making the worker tab available for reuse.

Medium BH2D-007

Malformed IPC JSON is silently ignored instead of failing the connection

Commit acaa69a context · harness/connect/client.py:346–350 · harness/aio.py:350–354

Both client frontends catch JSONDecodeError and return. After an invalid frame, the reader stays alive and pending requests keep waiting without a recorded failure cause.

Impact

The caller eventually receives a timeout instead of the immediate ProtocolMismatch that identifies the broken framing.

Recommendation

Treat malformed newline-delimited JSON as a terminal protocol failure, close the connection, and fail every pending request with the original parse cause.

Medium/low BH2D-008

The new Joblens collector can underfill and duplicate its output

Commit 0b47f0b · tools/fetch_new_joblens_jobs.py:83–137

Search stops when 100 unseen IDs are collected. Direct-URL deduplication happens only during later detail resolution, but rejected rows are not replaced. Accepted direct URLs are not added to the in-run seen set.

Impact

The command can emit fewer than 100 jobs even when later pages contain eligible replacements, and two fresh IDs can emit the same application URL.

Recommendation

Resolve and deduplicate incrementally until 100 accepted rows are obtained or all sources are exhausted. Rank only accepted rows and add every accepted URL to the set immediately.

What today’s Claude transcript clarified

The transcript explains intent and root cause, but it does not override the repository. Its selected top-five work included target ownership, the bounded target cursor, skill path containment, untracking personal data, and an outbound daemon queue.

The privacy files were initially staged for index deletion. A later git reset split the work into seven commits; the final staging command added the still-present files instead of restoring their deletions. That sequence produced the mismatch between the commit subject and Git state.

The transcript also confirms that target filtering was designed around _on_event bookkeeping, which explains why the separate click waiter escaped the fix. The daemon outbound queue was explicitly left for later. The macOS helper was intended as a v1-style port with automatic handshake timing; browser/PID scoping was not part of that design.

Model, harness, daemon, and CDP communication

The model owns semantic interpretation and chooses an explicit operation. The harness owns target identity, mechanical safety, routing, transport, typed outcomes, and cleanup. There is deliberately no direct model-to-CDP path.

What the range got right

  • Dead connections now tell the truth.The connection records the actual pump failure, daemon health follows browser health, and stale sockets can be replaced.
  • Skill bodies are meaningfully contained.The loader now defends against traversal, absolute paths, symlink escape, digest mismatch, and load-time replacement.
  • Parallel recording no longer serializes workers.The lock protects frame numbering rather than the entire capture operation.
  • The async frontend is now credible.Large replies, lifecycle ownership, and loop affinity are tested, including the corrected short macOS socket fixture path.
  • Target bookkeeping is directionally correct.Opener ownership and monotonic sequence numbers are the right invariants even though one waiter still bypasses them.
  • Packaging is explicit.The source distribution is an allowlist, preventing arbitrary working-tree files from silently entering an immutable release.

Recommended repair order

  1. Correct the Git index immediately.Untrack jobs.json and required.txt; verify from a clean clone. Treat history rewriting as a separate owner decision.
  2. Restore real hit-test ownership for click fallback.Keep the zero-rectangle rescue without allowing painted, obscured refs to bypass the element at the click point.
  3. Make popup waiting opener-aware.Apply the target-ownership predicate before an event can wake the click, not only before it enters the returned delta.
  4. Bind macOS approval to resolved browser identity.Pass application/PID/profile context into the approver and arm it only for the new handshake that needs consent.
  5. Add bounded quiet windows at asynchronous boundaries.Cover late OOPIF insertion and late popup creation without restoring unconditional fixed sleeps.
  6. Fail malformed IPC frames immediately.Both sync and async clients should close and fail pending requests with a typed protocol cause.
  7. Remove the daemon reader’s blocking peer write.Use a bounded outbound queue or a short send timeout and peer eviction so one client cannot stall all CDP traffic.
  8. Make the collector fill after deduplication.Resolve, deduplicate, and continue searching until the accepted target count is reached or sources are exhausted.

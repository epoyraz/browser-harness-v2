# ATS map run — 500 employers, 2026-08-29

The task: for the 500 employers with the most jobs on joblens.ch, follow one job ad to the
page where the application happens and classify the system and the flow (form / account
wall). Three browser passes over `parallel()` and one sequential foreground pass; scripts
and outputs live outside the harness in `../ats-map/`. What follows is what the run taught
about the harness, each with the measurement that says so, and what changed because of it.

## Wall clock and decisions

| Pass | Items | Workers | Wall | Per item (per worker) | Model calls to run it |
|---|---:|---:|---:|---:|---:|
| chain-follow, hidden tabs | 500 (225 real; see disconnect) | 6 | 433 s | ~11 s | 1 launch + 3 progress events |
| retry, hidden tabs | 347 | 5 | 792 s | ~11 s | 1 + 3 |
| foreground, one tab | 143 | 1 | 2 676 s | 18.7 s | 1 + 4 |

The "long runs are one decision" rule held: ~1 000 page chains cost a handful of model
invocations. The per-item time is dominated by *waiting for pages that were never going to
render* (below), not by CDP.

## Findings that changed code

**1. Shadow DOM was invisible to every query.** `jobs.smartrecruiters.com/oneclick-ui`
mounts the whole application form under 1 798 open shadow hosts. `document.querySelectorAll`
returns nothing, so `find()`, `form_schema()` and `read_page()` reported an empty page with an
"Apply" button, and 14 of 14 SmartRecruiters employers classified as "no form found". After
`deepAll()` (page.py `_DEEP_ALL_JS`, runtime `__bh.deepAll`): `form_schema()` → 8 fields +
2 file inputs on the same URL. Newly discovered roots also join the mutation observer, so a
click whose effect lands in shadow content is a counted consequence, not `unverified_mutation`.

**2. Some application SPAs paint nothing in a hidden tab — ever.** Abacus Umantis'
jobportal (`app.jobportal.abaservices.ch`), pastaHR and Workday's apply page: 0 body bytes at
5 s, 10 s and 15 s in a background tab; 427 bytes / 59 controls 4 s after
`Target.activateTarget`. 27 of the 500 chains ended on such a page. The digest now reports
`rendered {text_chars, controls, elements, visibility}`, `blank_while_hidden` and a `hint`
naming `activate_tab()`; the caller's settle loop (12 s + 10 s extra here) can stop at the
first read instead. Activation stays explicit — `parallel()` workers must not fight over the
selected tab — so those items belong in a sequential foreground pass; that pass took 18.7
s/item against 11 s hidden.

**3. `challenge.detected` was a captcha detector, not a wall detector.** Insel Gruppe's
application form (13 visible fields) loads reCAPTCHA to guard its submit and came back
`detected: true, confidence: high` — the same verdict as a Cloudflare interstitial. A
classifier that honoured the flag marked 23 of the first 53 employers "blocked"; 21 of them
had a full form on screen. Now `kind: wall | embedded | none`; `detected` is true for walls
only (verification text, or captcha markers on a page with ≤ 1 visible control and < 2.5 KB
of prose). Insel: `kind: embedded, detected: false`, 16 fields.

**4. A dead browser became 265 instant per-item failures.** The CDP connection dropped
after ~225 items; every remaining claim failed on `new_tab` within seconds and the summary
read `ok: 232, failed: 268` for a run whose work was fine. `parallel()` now cancels on
`browser_disconnected`; unstarted items carry that class and `did not start` in the error,
which is what a resume needs.

**5. `form.action` is a property that a control can shadow.** Three career sites have an
`<input name="action">`; `form.action` then returns the element and the read threw
`TypeError: (f.action || "").slice`. The dry-run guard and the danger probe read the
attribute now.

## Costs observed but not changed

- Cleanup accounting: 268 records ended `ok: false, class: resource_cleanup_failed` although
  every `value` was present — the disconnect made the tab release fail *after* the item had
  returned. Rule 4 wants the leak counted; a caller filtering on `ok` still loses good work.
  Left as is; `summarise()` is the place to separate the two if it recurs.
- `open_page()`'s adaptive early return accepts a parsed-but-empty SPA shell as "usable"
  when two probes agree; on hidden tabs that is exactly the blank document above. The new
  `rendered`/`blank_while_hidden` fields make it visible rather than changing the landing
  contract.
- The 200–800 ms opener-tree quiet window per item is ~2 % of the hidden-tab item time.
